# Study Workflow

このリポジトリで演習を進めるときの運用ルールです。

## 基本方針

各テーマは、問題を解く力を優先して進めます。
最初から正答や解説を読まず、本番に近い形で自分の解答を書きます。

## テーマごとの流れ

1. 問題を準備する
2. 本番のように解く
3. 解答を確認する
4. 正答を別関数で残す
5. 繰り返しそうなミスを記録する

## 1. 問題を準備する

各テーマに入る前に、問題ファイルを作ります。
この段階では、問題文、入力形式、出力形式、サンプルだけを書きます。

解答、模範解答、別解、詳しい解説はまだ書きません。

## 2. 本番のように解く

自分の解答は `main()` に書きます。

```python
def main():
    # 自分の解答
    pass
```

詰まった場合は、まずヒントだけを確認します。
正答は「正答を書いて」と明示した後にだけ追加します。

## 3. 解答を確認する

解答後は、次を確認します。

- サンプル入力で期待出力になるか
- `Yes` / `No` の両方がある問題なら両ケースを試したか
- 境界ケースで壊れないか
- 問題文の値を固定していないか
- 見つからなかった場合の出力を忘れていないか

間違いがある場合は、どこが原因かを確認します。
自分の解答は学習記録として残します。

## 4. 正答を別関数で残す

確認後、正答は `model_answer()` に書きます。
`main()` は自分の解答として残します。

```python
def main():
    # 自分の解答
    pass


def model_answer():
    # 正答
    pass


if __name__ == "__main__":
    main()
```

必要に応じて、別解は `another_answer_with_xxx()` のような名前で追加します。

## 5. ミスを記録する

今後も気をつけたいミスは `notes/mistakes.md` に追加します。
単なるタイプミスよりも、判断ミス、読み間違い、典型の見落としを優先して記録します。

例:

- `break` は一番内側のループしか抜けない。探索全体を終えるなら `return` を使う。
- `K` 個選ぶ問題で、サンプルの値に合わせて `3` と固定しない。入力値 `k` を使う。
- 見つからなかった場合の `No` 出力を忘れない。
