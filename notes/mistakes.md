# Mistakes

間違えた実装、見抜けなかった典型、境界条件ミスを記録します。

例:

- `deque` を使うべきところで `list.pop(0)` を使った
- 二分探索の `ok` / `ng` の意味が途中で逆になった
- 累積和の区間 `[l, r)` と `[l, r]` を混同した

## 00_io_basics

- 辞書で頻度カウントするとき、存在しないキーをそのまま `counts[x] += 1` すると `KeyError` になる。数えたい値だけを対象にするなら `if x in counts:` を入れる。
- ペアを作る問題で `set(a)` にしてから組み合わせると、同じ値が複数ある情報が消える。問題文の「異なる2つの要素」は、値が異なるという意味ではなく、位置が異なるという意味のことが多い。

## 01_bruteforce

- `break` は一番内側のループしか抜けない。答えが見つかった時点で探索全体を終えるなら `return` を使う。
- `Yes` / `No` を出す問題では、見つかった場合だけでなく、最後まで見つからなかった場合の `No` も書く。
- 「各要素を選ぶ/選ばない」は 0 個から N 個まで全ての選び方を含む。1 個や 2 個だけの組合せに限定しない。
- `K` 個選ぶ問題で、サンプルの値に合わせて `3` と固定しない。入力で受け取った `k` を使う。
- 最大値を求めるときの初期値を `1` などに固定すると、負の数だけの入力で壊れる。十分小さい値から始める。
- 入力で受け取った変数名と、後で参照する変数名を揃える。`d` として読んだのに `dist` を参照すると `NameError` になる。
- 添字そのものが不要なときは、`range(len(a))` より `for value in a:` の方が読みやすい。
